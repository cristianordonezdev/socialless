# Privacy and service boundaries

SocialLess has no account, server, advertising ID, analytics SDK or tracking. With user-visible local history enabled, it stores platform, intention, demo/website mode, session UUID, start/end/checkpoint timestamps, measured active duration, configured duration and completion reason. Disabling history stops future session/checkpoint writes; confirmed deletion removes existing records.

SocialLess never extracts website credentials, cookies, authentication tokens, message text or browsing history for app storage. At the user’s explicit request, it can import account names from a user-selected Instagram following export. Only normalized account names and the local import date are saved in a separate protected, backup-excluded file after preview confirmation; the export file, URLs and other export fields are not copied. A separate Delete following list action removes that copy without deleting the source export, history or login. This user-authorized scope extension is recorded in ADR-016; the original source specification remains unchanged. WebKit manages the website’s ordinary persistent data; a separate confirmed action clears all WebKit data belonging to this app. It cannot clear Safari or native-app sessions. Demo mode uses an ephemeral store and bundled pages with a restrictive CSP and no remote resources.

Demo filter preferences (platform, enabled flags and bundled rule IDs) are saved locally. Instagram website choices are saved only after the user enables Remember: master/per-rule flags, explicitly approved additional-rule IDs and the bundled catalog version. Check results and readiness stay in session memory only. Forgetting removes the saved choice without clearing website sign-in. The navigation engine examines navigation structure and parses link destinations transiently. The separate opt-in feed engine transiently compares author-area profile links/visible handles with the imported list and recognizes fixed short sponsored badges in that area, without saving website author identities, post text, labels or media. It never sends link URLs or page text to Swift, logs or storage. The isolated WebKit message handler accepts only a rule revision, enum health and bounded counts for known rule IDs; health is session memory only. No remote rule downloads or arbitrary selectors/scripts are accepted. A user-requested page check changes no content and never enables filtering automatically.

The website provider controls its own login, content and data collection. The app has no private API integration, proxy, network interception, user-agent spoofing or challenge bypass. HTTPS navigation is restricted by parsed host; no query-bearing URL or error payload is logged by app code. Public WebKit permission delegates deny camera/microphone requests. No native sensitive-resource permission descriptions or entitlement requests are included.

SwiftData uses the app sandbox and OS-provided data protection. No cloud sync is configured. OS backups may include app data under the user’s device settings. There is no claim that deleting local data deletes the provider’s records or existing backups.

The bundled privacy manifest declares no developer data collection/tracking and app-only UserDefaults use (`CA92.1`). The timer uses `ContinuousClock`, not a direct `systemUptime`/`mach_absolute_time` call. Re-audit the manifest and privacy disclosures whenever APIs, extensions or data flows change.

## Review before real embedded use or distribution

The app is a personal prototype, not an approved third-party client. Service terms/permission review, the remaining website device QA and App Store review are still pending. Do not equate a successful simulator build or one user report with provider authorization or App Store eligibility. The user reported Instagram Reels hide/restore success and retained activation in a new session. Explore hiding is also user-reported; Explore restoration, process relaunch, following import/feed filtering and remaining device scenarios are unverified; Facebook/TikTok filters and Screen Time are unavailable. Any future shield blocks the whole chosen app and needs separate entitlement/device validation.

Official references consulted during implementation (2026-11-09):

- [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) — review third-party service permission and minimum functionality requirements before distribution.
- [WebKit navigation delegate](https://developer.apple.com/documentation/webkit/wknavigationdelegate) and [WKWebView](https://developer.apple.com/documentation/webkit/wkwebview) — public browser APIs; installed Xcode 27 headers were also inspected for exact signatures.
- [ContinuousClock](https://developer.apple.com/documentation/swift/continuousclock) — clock abstraction; elapsed-duration behavior is covered by injected-clock tests.
- [SwiftData](https://developer.apple.com/documentation/swiftdata) — native local persistence, verified with a recreated store test.
- [Privacy accessed API categories and reasons](https://developer.apple.com/documentation/bundleresources/app-privacy-configuration/nsprivacyaccessedapitypes/nsprivacyaccessedapitype) and [TN3183](https://developer.apple.com/documentation/technotes/tn3183-adding-required-reason-api-entries-to-your-privacy-manifest).
