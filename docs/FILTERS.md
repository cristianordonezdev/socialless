# Reversible filters

The engine is available for all three **offline demos**. Instagram also has an **Experimental Reels / Explore navigation pilot 0.3.0**, gated by a manual check or explicit remembered consent with automatic compatibility checking. Facebook and TikTok website catalogs remain empty and Unavailable. After an initial failed check on 2026-11-13, the user reported that the corrected filter hides the Reels entries. The prior device context is iPhone 13 Pro / iOS 27.2; the user subsequently confirmed restoration and access to messages/stories while filtering. The user also reported that Reels stayed active after ending/reopening a session. Process relaunch, remembered Off and Explore still need device confirmation. See `PLATFORM_COMPATIBILITY.md` for the exact evidence.

## User behavior

Start an Offline demo → Filters → Enable demo filters. Only the fictional Discover and Short videos navigation links disappear. Turn off either rule or the main switch to restore its links without reloading. The timer continues while the sheet is open. Settings → platform → Try demo filters offers the same preferences.

Demo preferences are separate per platform and survive relaunch. Missing filter fields default off; existing filter choices, history preferences, platform selection and time limits are preserved. Website choices are session-local by default. After an active Instagram trial, Remember for Instagram saves master/per-rule choices, explicit additional-rule consent IDs and the catalog version; matching consent survives completion and app relaunch. Off is saved too. Old or missing catalog consent starts a fresh session off. Turning Remember off keeps the current session choices and clears saved consent; Settings can also forget them. Reset preferences clears both demo and website choices. WebKit sign-in persistence is independent and unchanged.

Explore starts off and requires its own **Check Explore link** probe. That probe uses a separate revision and never replaces or disposes the active filter runtime. A successful probe unlocks only Explore; an explicit switch change is still needed. Checking Explore alone can also enable an Explore-only trial while unapproved Reels stays untouched. Probe results are canceled on navigation, pause, failure or shutdown. Remembering Reels does not grant Explore consent; only separately checked and explicitly selected Explore choices can be remembered.

In an Instagram website session without remembered consent, open **Filters → Check Reels link**. The one-shot check only counts visible, compatible navigation anchors; it changes no DOM and starts no observer. A match unlocks **Enable experimental filters**, which remains off until explicitly switched on. No match leaves it locked, with an explanation and retry. No link URL or content crosses the JavaScript bridge. The successful check is held in memory for that session, while the runtime rechecks host/path guards on every document. Pause or navigation cancels an unfinished check; page failure revokes readiness. Off restores links immediately without reload.

Health distinguishes waiting, checking, compatible link found, off, active, no matching links, unsupported layout, partial coverage, style blocking, paused, unavailable and failed. A match count means navigation links matched, not that recommendations or feed posts were removed. Counts and health are held only in memory. An unsupported layout means a visible link has the exact candidate destination but lacks a recognized navigation control; it is left visible. Partial coverage means supported controls were hidden while other exact-destination links remain visible. Neither status claims that the Reels section was eliminated.

## Catalog and execution contract

- `Resources/Rules/{platform}_demo_rules.json` and `{platform}_rules.json` have schema version 1, semantic rule version, exact platform, mode scope, availability and rules. Missing/malformed catalogs fail independently, leaving timed browsing usable.
- `hideAnchorByPath` supports segment-boundary prefixes in the demo. `hideAnchorByExactPath` supports exact destinations inside semantic navigation. `hideInstagramReelsNavigation` additionally supports an anchor labeled `Reels` or containing an SVG with that accessibility label. `hideInstagramExploreNavigation` uses the same narrow structure with an Explore label and exact `/explore`. The registry restricts both kinds to Instagram website scope and their respective exact destination, with an optional trailing slash. Explore subpaths such as search, tags and locations are excluded. Unknown kinds/versions, duplicate/unsafe IDs, mismatched platform/mode, malformed paths, root-wide prefixes and protected auth/account/consent/recovery paths are rejected. No arbitrary selectors, code or remote configuration.
- Prefixes are normalized without a trailing slash. `/sample/discover` matches itself or `/sample/discover/…`, not `/sample/discover-more`; queries/fragments do not affect matching. Anchor URLs must be first-party HTTPS on the selected platform, with no userinfo or alternate port. Encoded protected/ambiguous routes are excluded too.
- Generic rules use `nav a[href], [role="navigation"] a[href]`. The Instagram rule examines bounded `a[href]` candidates, first validates the exact first-party destination, then requires semantic navigation or the fixed Reels accessibility hint. It does not use class names, post text or broad video selectors. Article/form/dialog links remain excluded even if they carry that hint. Individual `/reel/...` or `/reels/...` links are excluded. Unknown buttons without a supported destination remain untouched. No text, labels or URLs cross the bridge; only known health states and bounded counts do.
- `WKUserScript` injects the bundled `filter_engine.js` at document end, main frame only, in `SocialLess.Filters`. The runtime independently guards the selected HTTPS host (exact or dot-subdomain). Demo scope accepts only `about:blank` in the session's local-only WebView. An empty website catalog installs **no script**.
- Remembered consent is valid only for the selected Instagram website catalog version. Before automatic hiding, each pass requires a visible supported target (or a previously app-hidden target still matching) and no visible unsupported Reels destinations. Partial layouts restore the affected rule’s automatic changes while compatible independent rules can continue. A selected Instagram rule with no match also produces partial health if another rule is active. The observer can retry late-rendered controls, with no polling. Manual one-shot checking remains read-only; auto checking does not persist readiness.
- A per-instance unique marker and scoped CSS hide matching anchors. Original `hidden`, inline styles, classes and DOM structure stay intact. Off/dispose removes only owned markers/style; a pre-hidden element stays pre-hidden. The website can still see DOM changes; a content world isolates globals, not the DOM.
- A 300ms coalescing observer watches subtree changes plus `href`, `role`, `aria-label`, `hidden`, `class`, `style` and the app-owned marker, with no polling. The observer disconnects for app writes, preventing recursion. If a page removes the marker, the next pass reconciles it; if the page overrides hiding, the runtime restores its changes and reports style blocking. Each pass allows at most 1,000 candidate anchors and 20 rules. Exceeding the bound or an exception also disconnects and restores app changes. This bound is an overload fallback, not a physical-device battery benchmark.
- Native URL observation reapplies host/route guards on SPA history changes without patching the website's JavaScript. New documents receive current preferences. Backgrounding stops observation; resume reconciles the current page. Shutdown removes user scripts, the message handler, URL observation, scheduled work and app-owned DOM state as feasible before browser teardown.
- An isolated handler accepts current-revision, main-frame state and bounded counts for known rule IDs. No text, href, input data or cookies are transmitted, logged or stored. Weak callbacks avoid a handler/controller retain cycle.

## Tests and gates

`FilterRuleTests` covers all bundled catalogs, malformed schemas/types/paths, platform/mode scoping and backward-compatible preferences. `FilterEngineTests` executes real WebKit against local synthetic HTML, including first-party-looking base URLs with **no remote loads**: exact restoration, pre-hidden state, unrelated elements, host/path/auth guards, isolated globals, dynamic subtrees, mutation bursts, href changes, no loops, paused/off/disposed state, SPA routes, CSS failure, overload and all three app demos. `FilterControlsUITests` exercises real switches, page visibility, persisted preferences and platform isolation. Actual run results belong in `IMPLEMENTATION_STATUS.md`.

Before enabling website defaults or marking integration Verified: observe a permitted real-device session, record platform/device/OS/date/app/rule version, establish a narrowly scoped navigation target, add sanitized synthetic fixtures, verify auth/consent/recovery and SPA behavior, verify Off restores the page, and update the capability matrix. User-reported hide/restore and continued messages/stories access support the current optional remembered trial, with runtime compatibility checks and version-scoped consent. Broader device gates remain open; a positive count is not a completed manual QA result. Keep availability Experimental while website behavior can change. Do not infer real selectors from the demo's fictional `/socialless-demo/` routes.

`InstagramFilterPilotTests` uses fictional local HTML with no remote loads to test the read-only gate, exact routes, hidden-layout rejection, restoration, SPA auth guards, pause/resume, late/canceled checks, fresh sessions, terminal shutdown and CSS failure. Added cases cover unmarked labeled controls, unsupported/partial coverage, changing icon labels, unsafe lookalikes, removed markers and later style overrides. The UI tests use the unmarked synthetic layout and exercise check → opt-in → Off → new session, plus remembered On/Off across actual process relaunch and forgetting without changing the current page. Automatic checking is covered against hidden/late controls, partial/new layouts, auth routes, pause/failure/terminal states and CSS blocking. Persistence tests cover old settings migration, per-rule choices, scope isolation, version changes and revocation. Its fictional website fixture and launch switch compile only in Debug, use an ephemeral store, and require both UI-testing flags. These fixtures are not captured Instagram HTML.

Limitations: no route blocking or redirecting; no feed-item filtering, friends detector, autoplay control or native-app modification. No cross-origin auth exceptions or embedding bypass. A website may use a different navigation structure or disallow injected CSS; basic timed browsing is the fallback. Physical-device filter performance, accessibility and the remaining service scenarios are pending.


## Imported-account feed pilot (separate from catalog 0.3.0)

User-authorized scope extension: see ADR-016. Settings → Instagram → Import following list accepts a single unzipped following.json from an Instagram JSON export. Preview and Save/Replace are required. No ZIP/HTML parser or automatic download is implemented. Imported handles are local settings chosen by the user, not website-extracted data. Delete is separate from history/login and does not touch the source file.

During an Instagram website session, Filters → Only imported accounts enables a separate runtime. It starts Off each session, including with Remember for Instagram enabled. Replacing/deleting the list disables it. The home route must be exact HTTPS Instagram `/` without a query. Candidate posts require a semantic main/article, exactly one header with a unique profile handle whose visible text matches its link, and a first-party `/p/…` or `/reel/…` permalink containing a time element. Ambiguous authors, collaborations and unsupported structures are left visible. Posts from recognized imported authors stay; recognized other authors are hidden. The runtime never loads additional posts. A sparse/empty feed is possible, and an old or wrong-account snapshot can give unwanted results.

The separate isolated world uses no document-start user scripts, so feed filtering may begin after load and briefly show content. Reconciled on document finish and SPA URL changes; a 300ms observer handles in-place author/recycled post changes. Work bounds: 500 articles, 100 links/article, 10,000 imported accounts. Markers and style only; restoration leaves original attributes intact. Off/pause/failure/navigation/terminal shutdown dispose observer/timer and restore. CSS blocking and overload restore and report failure. Native messages carry only revision, enum status and bounded aggregate counts; neither authors nor URLs cross back to Swift.

Live Instagram DOM support and physical Files import remain unverified. No selector is represented as observed live markup. Keep Experimental; unsupported layouts must remain usable with an honest status.


### Feed detector correction — 2026-11-14

Supersedes the initial mandatory-header/timestamp restriction above. User reported 7 unrecognized posts and 0 hidden. Synthetic regressions reproduce that detector gap; they are not captured real markup. A semantic header plus post permalink no longer requires a time element. For cards without a header/permalink, a unique profile link naming itself before visible >=120 × 120 content media can identify the author. Semantic article/main boundaries remain mandatory; captions, paragraphs, quotes, dialogs/forms/navigation/footer, multiple authors and unsupported structures stay visible. Work remains bounded. Hidden feed cards now collapse their outer height, vertical padding/margins and borders with clipped overflow, visibility and opacity CSS. They do not reserve their original space. Only changed classifications update markers; stable cards are never temporarily shown for measurement. Previously measured media-node identity is held in a WeakSet so percentage-sized media shrinking with a collapsed parent cannot cause repeated hide/restore loops; author links are still re-evaluated. Duplicate same-document refreshes reuse the owned runtime, and unchanged health reports are suppressed. Hidden cards are inert; owned inert attributes and capture listeners are removed on disposal, preserving pre-existing inert attributes. Capture guards stop activation events originating in hidden cards while leaving touch/pointer default scrolling intact. This is not a global Reels route blocker and unknown cards remain visible. Off restores original DOM layout. Initial activation/restoration can move content as card heights change; stable reevaluation must not. Website wrappers/gaps or unrecognized layouts may still leave space. This does not stop media downloads or promise to pause individual hidden videos.

Exact short Sponsored/Publicidad/Patrocinado/Patrocinada badges in the author area identify sponsored cards. Profile handles named sponsored and caption mentions do not qualify. Such cards hide while Only imported accounts is On, even if the recognized advertiser is in the list. There is no standalone/global ad blocker, network blocking, language-complete detection or guarantee that all ads disappear. Only enum/count health is sent to native UI. No new fields are persisted. Found-but-unrecognized posts now have a separate explanatory status from an empty/unsupported feed.

## Strict imported accounts and video behavior — 2026-11-14

Supersedes the unknown-author fail-open behavior described in earlier milestones. With Only imported accounts enabled, top-level home-feed article candidates are collapsed unless their recognized author is in the imported following list; recognized ads are also collapsed. Unrecognized is now a subset of Hidden posts, and those cards can include valid followed accounts. Protected forms/dialogs/navigation and nested article boundaries are excluded. Content outside supported article boundaries may still escape detection; this is not a guaranteed friends-only feed. Off restores the original page. The list is following (accounts the user follows), not followers. No source export needs reimporting.

Website sessions now allow inline video playback, disable element fullscreen, and retain WebKit's all-media user-action requirement. A document-start isolated-world DOM policy prepares dynamically inserted videos with playsinline, removes autoplay, and pauses play events without a trusted click on that video. Scroll and synthetic clicks cannot authorize playback. No website play/fullscreen APIs are patched, and no media content or event data is logged/stored. Custom play overlays and native controls need physical QA; this may conservatively block some deliberate playback. This does not prevent downloads or website-created CSS fullscreen layouts. Demo receives no media policy script.

## New candidate visibility — 2026-11-14

Feed-only mutation processing now runs before rendering rather than after a 300ms delay. Persistent candidate CSS hides unapproved top-level article cards; a recognized allowed author grants an owned approval marker. Rejected cards collapse as before. Both approval/rejection markers restore on teardown, and navigation filters retain their independent scheduling. This prevents supported newly inserted cards from being displayed during the former debounce window. Initial load before enabling the filter and unsupported layouts are not covered. This does not control Instagram pagination or guarantee more matching posts; the repeated no-match batch behavior remains an open product/device gate.

## Finite feed boundary — 2026-11-14

User chose ending the feed after a newly inserted batch without approved cards. Initial mounted cards form a baseline; new candidate nodes settle for 500ms after insertion. At least one approved node keeps the feed open. A connected batch with no approved cards latches an end state; native code unloads the live document and shows No more matching posts with Try again and End session. The timer continues. Retry loads home retaining the filter opt-in and ordinary WebKit sign-in storage. This does not prove that no further matching posts exist, and does not access/intercept pagination endpoints. Node reuse, unsupported layouts and slow hydration remain limitations. Pending batches cancel with disposal/Off/pause/route exit. End state survives normal lifecycle callbacks until explicit retry; terminal sessions cannot retry.

## Independent Stories pilot — 2026-11-14

Filters → Experimental · Stories → Filter stories starts Off each session. Separate isolated world/controller, markers, observer and health avoid interfering with feed/nav filters. A saved following list is used if present; replacement/deletion turns Stories filtering Off as well as feed filtering. No list means recognized ads only. Candidate route requires secure Instagram first-party host/port, /stories/handle/numeric-id, one outer semantic main/dialog and one header. Exact Sponsored/Publicidad/Patrocinado/Patrocinada leaf badges in the header exclude captions/forms/navigation and self-naming profile links. Account named sponsored is not an ad label. Route account matching uses the imported list transiently, never stores story URL/content/author. Highlights/auth/DM/home/foreign and unsupported structures are excluded. No live markup was inspected.

A recognized blocked viewer is visibility/opacity hidden and inert, videos paused, with a native Story hidden shield offering Back to Instagram or Turn off story filter. No next-control guessing or automatic skipping. Off/pause/navigation/failure/terminal cleanup restores owned DOM state. Native messages contain revision/enum/counts only. CSS blocking restores and reports failure. Unsupported/ad labels outside supported header structure can remain visible; initial loading before script evaluation can flash content. The playback policy remains independent. Physical current Instagram Stories detection, restore, navigation, media and accessibility need QA before any stronger claim.

## Strict Stories imported-author policy — 2026-11-16

Supersedes route-account approval and fail-open unsupported viewers from ADR-017. With a saved imported list and Filter stories On, only a single identifiable author from the displayed header/before-media area can allow the story. The URL is used only for secure Stories scope, never as author evidence. A differing/missing/ambiguous author or missing/ambiguous viewer is covered by the native shield. No numeric story ID or semantic header is required when an author-before-media layout can be identified. Exact ad labels in that same area still block followed accounts. Unknown status explains potential false positives and late hydration can reclassify automatically. CSS rejection in strict mode keeps the native shield; Off removes it. No-list mode retains ad-only behavior and unsupported coverage limitations. Captions, protected routes, foreign origins, source data and login remain unaffected. This is synthetic candidate coverage pending device QA.

## Stories false-positive policy correction — 2026-11-16

Supersedes the strict unknown-author shield. User reports all friends' stories were blocked; unknown/ambiguous/unsupported stories now remain visible with explicit unrecognized health. Only positive ad-label or outside-list author evidence can hide. Semantic header profile links may display a name/avatar/verification badge; self-naming text remains required in the unmarked before-media fallback. Route accounts still do not authorize a story. Native blockedSponsored versus blockedAccount reasons are separate; unknown authors are never classified as sponsored. CSS failure restores and reports inability to hide. This trades incomplete ad coverage for usable access to friends while current markup is unverified. Existing list, Off/session scope and privacy behavior remain unchanged.
